# QA, November 2026

A sweep of Text to Robot for problems a visitor or a builder would meet: the owner's reports, the code scanning and
dependency alerts, every export opened with its own tool, and the live site used as a visitor. Each problem has a severity
(**high**: wrong robot, a broken file or a page that can hang; **medium**: a real defect with a workaround; **low**: polish)
and what was done about it. Fixes landed one by one, each with its test.

## Found and fixed

| # | Where | Problem | Severity | Fix |
|---|---|---|---|---|
| 1 | Modify | "Change to red colour and only 4 wheels" turned only the small accent parts red; a change the design's own request could not hold (another wheel count, more or fewer arms, a look, a size) was refused, and on a work cell (no in-place editor) generic parts were stacked on the robot | high | the robot is read back into its plan, the change edits the plan and it is designed again; every changed field is said; `undo` (replan.ts, tests/fidelity/modify.test.ts) |
| 2 | Designs | prompts for different jobs gave identical-looking robots | medium | style words bring a shell and palette, a job its own palette (tests/fidelity/variety.test.ts) |
| 3 | Work cell | a work cell asked for with a camera failed `wiring:ports` (the wrist camera's CSI port was never wired or spared) and its arms' cameras were not robot sensors | medium | arm sensors are grafted with the arm and spared like a single arm's |
| 4 | Humanoid | the back switch case overlapped the torso by 0.2 mm (`clearance:home` failed whenever the switch fitted in neither panel) | medium | the case stops at the torso's back face |
| 5 | Parser | regular expressions with quadratic backtracking (CodeQL js/polynomial-redos) in fidelity.ts, request.ts, triage.ts, inventory.ts, parts-mode.ts and wiring.ts: a long adversarial prompt could stall the tab | high | rewritten as word-by-word readers or bounded patterns; 10,000-character adversarial prompts read in under 50 ms (tests/adversarial-time.test.ts) |

| 7 | Bring your own model | an OpenAI-compatible URL was taken for OpenAI's own when "api.openai.com" appeared anywhere in it (CodeQL js/regex/missing-regexp-anchor) | low | the host itself is compared |
| 8 | Forge worker | a pool job named the body part to forge by a key used straight as a property (CodeQL js/unvalidated-dynamic-method-call) | low | only BUILD's own parts are run |

| 11 | Engine API | the engine API (used by other pages) read a robot file's names as object keys before validating it; only the import path validated, after finalizing | medium | every robot sent to the engine API or imported has its names checked first (`badName`, robot-schema); a part named `__proto__` is refused |

| 15 | Parser | "a two wheeled balancing robot" built a base on casters without saying balancing is not designed | medium | said |
| 16 | Parser | "a cheap arduino robot for my 10 year old" found no robot type and built the 6 DOF arm | medium | "Arduino robot" with no body named builds the Arduino car, said |

| 18 | Modify | "change to red colour" on the rover left its big aluminium body grey (only printed parts were painted) | high | a cut aluminium body is powder-coated in the colour too |
| 19 | Modify | a colour was lost when a later change re-planned the robot after an in-place one ("change the arm to 4 dof" then "remove one arm" turned a red rover white) | high | the colour, palette and first prompt go with the robot through every redesign |

## Reviewed, not changed

| Alert | Why it is not a defect here |
|---|---|
| js/remote-property-injection (kin.ts, wires.ts, esim/robot.ts, arduino/plan.ts, urdf-validator xml.ts, engine edit.ts) | the keys are link, joint and part names; since fix 11 every name in a file from outside is checked (`badName`: no `__proto__`, `constructor` or `prototype`) before any of these run |
| js/missing-origin-check (browser-engine.ts, forge poolworker.ts) | dedicated workers: only the page that started them can post to them |
| js/file-system-race, js/insecure-temporary-file (scripts/) | developer scripts run by hand on the developer's own files |
| js/regex/missing-regexp-anchor in tests/ | test assertions on fixed strings |
